---
title: "Protocol reference"
---

Send one JSON object per WebSocket **text frame**. The `type` discriminator is required and case-sensitive. Each required field must have the documented type. Invalid JSON, unknown message types, and invalid field types are logged and ignored. Binary messages are ignored. Messages and frames are limited to 1 MiB; exceeding the transport limit can close the connection.

### voice\_state

Send the complete roster when someone joins, leaves, speaks, mutes, or changes their name or color. It replaces the previous roster.

```json
{
  "type": "voice_state",
  "in_call": true,
  "members": [{
    "id": "user-42",
    "name": "Mara",
    "avatar_url": "https://example.com/avatars/mara.png",
    "color": [103, 80, 164],
    "speaking": true,
    "muted": false,
    "is_self": false
  }]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `in_call` | boolean | Whether a call is active. False clears the roster and local mic/deafen state. |
| `members` | array | The complete list, in display order. |
| `id` | string | A stable member identifier. |
| `name` | string | Display name; its initial is the fallback avatar. |
| `avatar_url` | string or null, optional | Public HTTPS thumbnail URL, maximum 2,048 characters. Missing or failed images fall back to initials. |
| `color` | three integers | RGB values, each from 0 to 255. |
| `speaking` | boolean | Draws an active speaker border. |
| `muted` | boolean | Adds a microphone-off icon. |
| `is_self` | boolean | Marks the local user with “(you)”. |

To end a call:

```json
{ "type": "voice_state", "in_call": false, "members": [] }
```

### notification

```json
{ "type": "notification", "title": "Hello", "body": "Mara joined the call" }
```

Both fields are strings. The default display time is eight seconds with up to five cards, newest first. Users can change these limits or show titles only. Disabled notifications are discarded. Keep text short enough for a 320-pixel-wide card.

### mic\_state

```json
{ "type": "mic_state", "muted": true }
```

Updates the local mic display. A self member appears muted when either this value or their roster `muted` field is true. Keep both in sync when unmuting.

### deafen\_state

```json
{ "type": "deafen_state", "deafened": true }
```

Updates the control panel’s deafen display. This does not change actual audio or automatically mute the microphone.

### Protocol v2

After opening the socket, a call integration can introduce itself before sending its snapshot. A mute-only client sends:

```json
{ "type": "hello", "version": 2, "name": "Example voice plugin", "client_version": "1.4.0", "actions": ["set_mute"] }
```

Yaplay replies on that socket:

```json
{ "type": "hello_ack", "version": 2, "actions": ["set_mute"] }
```

`name` is required. The optional `client_version` identifies the plugin build. Both are self-reported display strings of 1–128 UTF-8 bytes, with visible content and no control characters. `version` is the wire protocol version. The required `actions` array contains strings. Yaplay accepts `set_mute`, `set_deafen`, and `leave_call`, ignores unknown action names, and returns each accepted action once.

An empty array identifies a roster-only call integration. Every valid v2 hello claims ownership of the call, even with an empty array. A notification-only sender should just send notifications. The latest negotiated socket owns the roster, mic, and deafen state. Taking over clears the previous call. Renegotiating on the same socket updates its actions and preserves its call. Closing the owner clears the call. Other sockets may continue sending notifications. Reconnect with a fresh hello and current snapshot.

Settings → General shows the active integration and its actions. The overlay shows its accepted controls and enables them during a call. Global mute and deafen shortcuts follow the same permissions.

### Compatibility

| Client | Yaplay with v2 | Yaplay with v1 only |
| --- | --- | --- |
| v2 call integration | Named, with the acknowledged actions | No acknowledgement. Continue publishing state. Fall back to v1 controls only if all three actions are implemented. |
| v1 control integration | Unnamed, all three controls | Unnamed, all three controls |
| State-only client without hello | Legacy state updates when no negotiated owner is active | Same behavior |

A v1 client sends the following on each connection. There is no reply.

```json
{ "type": "hello", "version": 1, "controls": true }
```

### Control requests

Yaplay sends one of these JSON text messages when a control is pressed:

```json
{ "type": "set_mute", "muted": true }
```

```json
{ "type": "set_deafen", "deafened": true }
```

```json
{ "type": "leave_call" }
```

Apply the requested state using your host's voice actions, then send the resulting roster, mic, and deafen state. The overlay does not update optimistically: microphone permissions and call roles may prevent a request from succeeding. Do not replay control requests after reconnecting. Disconnecting the active control client clears its roster and disables call controls. The Exit button still exits Yaplay rather than leaving the Yapin call.
