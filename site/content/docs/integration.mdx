---
title: "Build a Yapin integration"
---

Implement the integration inside your Yapin client modification, such as a Yapmod or Yap++ plugin. Subscribe to the host’s Yapin call, speaking, mute, deafen, and notification events.

The repository includes a <WrapperDownload /> (source: `examples/yaplay-client.mjs`). It retries connections, remembers the latest state, and replays that state after reconnecting. Notifications are sent only when connected and are not replayed.

## Try the transport with Node.js

This standalone example verifies the connection to Yaplay with sample data before you wire it to Yapin. Use a current Node.js LTS. Copy the wrapper next to a file called `demo.mjs`, install `ws`, then paste the following into that file:

```sh
npm install ws
node demo.mjs
```

```js
import WebSocket from 'ws';
import { YaplayClient } from './yaplay-client.mjs';

const overlay = new YaplayClient({
  port: 8080,
  WebSocketImpl: WebSocket,
  onStatus: (status) => console.log('Yaplay:', status),
});

// Prepare current state even if Yaplay is not yet running.
overlay.setRoster([{
  id: 'self', name: 'You', color: [103, 80, 164],
  speaking: false, muted: false, is_self: true,
}]);
overlay.setMic(false);
overlay.setDeafen(false);
overlay.connect();

process.on('SIGINT', () => {
  overlay.setRoster([], false); // Best-effort clear before closing.
  overlay.disconnect();
});
```

Start Yaplay and press Start before or after launching the example. The wrapper retries every 1.5 seconds while disconnected. `connect()` is idempotent; `disconnect()` cancels retries. Its methods return whether the message was sent immediately; state is still cached when the return value is false. This is not a delivery acknowledgement.

## Map Yapin’s state from your client modification

```js
// Adapt these fields to the Yapin state exposed by your client modification.
function publishCall(call, currentUserId) {
  overlay.setRoster(call.members.map((member) => ({
    id: String(member.id),
    name: member.displayName,
    avatar_url: member.avatarThumbnailUrl ?? null,
    color: member.rgb ?? [103, 80, 164],
    speaking: Boolean(member.isSpeaking),
    muted: Boolean(member.isMuted),
    is_self: member.id === currentUserId,
  })), call.active);
}

// Call these from your actual host event handlers:
// publishCall(currentCall, currentUserId);
// overlay.setMic(microphoneMuted);
// overlay.setDeafen(audioDeafened);
// overlay.notify('Call started', 'Your group is ready');
```

The field names and event handlers above are illustrative, not an existing Yapmod or Yap++ plugin API. Use the actual lifecycle and event methods of your chosen client modification, publish its current Yapin call state when the plugin enables, and unsubscribe on unload. This repository provides the transport wrapper, not a packaged plugin for either host.

If your client modification uses Rust, Python, or another language, use its WebSocket client and send the same JSON; the JavaScript wrapper is optional. Follow the [plugin lifecycle guide](/docs/lifecycle) to handle reconnects and cleanup.

## Handle overlay controls

Supply `name` to negotiate v2 on every connection. Set `actions` to the commands your callback implements. A named integration without a callback advertises an empty list and owns the roster. Leave `name` and `onControl` unset for a notification-only sender.

The wrapper publishes the snapshot immediately. With a name and all three actions, it falls back to v1 and republishes the snapshot after 1.5 seconds without a v2 acknowledgement. A partial-control client continues publishing state on older hosts. Its controls require v2. Existing unnamed wrappers keep their previous behavior.

```js
const overlay = new YaplayClient({
  WebSocketImpl: WebSocket,
  name: 'Example voice plugin',
  clientVersion: '1.4.0',
  actions: ['set_mute', 'set_deafen', 'leave_call'],
  onControl: async (action) => {
    // Illustrative host bridge: replace these methods with your host's APIs.
    try {
      if (action.type === 'set_mute') await host.voice.setMuted(action.muted);
      if (action.type === 'set_deafen') await host.voice.setDeafened(action.deafened);
      if (action.type === 'leave_call') await host.voice.leaveCall();
    } finally {
      // Publish actual state even when permissions or roles reject the request.
      publishCall(host.voice.currentCall(), host.currentUserId());
      overlay.setMic(host.voice.isMuted());
      overlay.setDeafen(host.voice.isDeafened());
    }
  },
  onControlError: (error) => console.error('Yaplay action failed:', error),
});
```

These are desired-state commands, not blind toggles. Host event subscriptions should also continue publishing updates. Callbacks run in order, and failed callbacks report to `onControlError` without stopping subsequent actions. Queued actions from closed connections are discarded and never replayed. Already-running host actions cannot be cancelled by disconnecting the wrapper.

Only the most recently negotiated integration owns call state and receives commands. Other connections can still send notifications. This prevents one button press from muting unrelated clients. The application Exit icon closes Yaplay; the phone icon requests leaving the Yapin call.
